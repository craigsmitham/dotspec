# Define the scope of a feature

Choose a stakeholder and a benefit they would recognize. Which product behaviors have to work together to deliver it? Ask someone returning to To-do what “pick up where I left off” entails. Finding the errand and recovering its last saved state both matter. A count of all open errands answers a different question about workload. This use of stakeholder value as the grouping criterion follows IREB. [IREB, *Glossary of Requirements Engineering Terminology*, v2.2.0, “Feature”](https://cpre.ireb.org/en/downloads-and-resources/glossary?first-letter=F&tag=cpre-glossary).

From the owning system or component directory, run `dotspec feature init resume-work`, using a lowercase, hyphenated name for your feature. If a declaration already exists, edit that `*.feature.spec.md` file. Give the feature its stakeholder-facing name in the top-level heading. Describe the available behavior under **Description** and its benefit under **Purpose**.

Under a level-two **Groups** heading, link to each specification that describes part of the behavior. In To-do the owner decides what to do about a waiting errand. Which promise lets them see that a call needs chasing today? Which lets them find the errand after a restart? Link to the return use case, the follow-up requirement and the restart requirement. A feature can also group a concept, a named concept use, a synchronization or an interface. Another feature that depends on the same guarantee can link to the same requirement. Keep the statement, conditions and criteria there. [Worked feature](../../../examples/todo/specs/features/pick-up-where-i-left-off.feature.spec.md#groups).

From the project root, run `dotspec model overview` and find your feature in the **Features** table. If a member is missing, check its target and the **Groups** heading in the feature file, then rerun the view. For each listed member, ask what would go unexplained if you removed it. If the only connection is a shared screen or team, remove that membership and check the scope again. [What holds a feature together?](../explanations/features.md).

Once the group is settled, try a case that makes two members apply at once. Can the system deliver the benefit while honoring both promises? [Review a set of requirements](review-a-set-of-requirements.md).
