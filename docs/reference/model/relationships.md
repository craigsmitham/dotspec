# Model relationships

Generated from [the canonical model](../../../model/dotspec.yaml). Do not edit this file.

Model `0.8.0-draft`. This lookup covers every record-reference field, including inherited endpoint refinements. Unchanged inherited fields are documented on their base class. Embedded values and their fields remain in the [complete reference](index.md).

Typed fields are authoritative. Assertions are optional derived views, not a complete substitute for those fields. `projection_path` retains the canonical field and role of each assertion. Reverse navigation is derived; stored owner backlinks are checked against canonical membership fields.

Cardinalities describe snapshots, including unfinished declarations. An optional resolved target does not mean a complete authored design can omit the definition it needs. Required list presence does not imply a nonempty list. Ordering preserves authored presentation unless a field explicitly says otherwise; it does not impose execution order. Cycle policies apply to the named relationship, not the entire graph: owner/member backlinks are intentionally reciprocal.

Relationship categories describe edges. They are independent of the core/supporting/generic classifications of model subsets.

## Relationship categories

| Category | Scope |
| --- | --- |
| Declaration containment | A declaration and its owned members; source-local, with checked owner backlinks. |
| Structural context | Directory-derived association and system hierarchy; no semantic inheritance. |
| Semantic association | Explicit domain claims with typed targets and relationship-specific scope. |
| Contextual citation | Authored reference occurrences; citations alone do not establish domain claims. |
| Derived projection | Optional assertion endpoints projected from canonical fields. |
| Source and inspection provenance | Evidence linking model records, source occurrences and inspection results. |
| Document representation | Syntax structure and indexes, rather than domain ownership. |
