# Layered requirements example

Follow a business goal and recovery policy through a user job, software use case,
a named concept use, an embedded obligation and its more precise requirement.
These are connected views; the folders do not prescribe authoring order.

```sh
dotspec model trace --path examples/requirements-traceability --relative-to docs/reference
```

The checked-in [generated view](../../docs/reference/requirements-traceability-example.md)
shows motivation, behavior, change-review candidates and verification guidance.
It is generated by `mise run generate`. No test execution or satisfaction verdict
is represented. See [Declare relationships](../../docs/develop-relationships.md)
for authoring syntax and [Requirements layers](../../docs/requirements-layers.md)
for the semantic distinctions.
