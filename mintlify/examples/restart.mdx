---
title: "What survives a restart?"
description: "Follow two everyday errands from a durability requirement to the test that kills and restarts the To-do service."
---

Yesterday you returned the library books and crossed them off. You still have a parcel to mail. The task service stops overnight. What should your list show this morning?

Walkthrough verified with dotspec `0.1.0-alpha.1`.

## Read the promise

Open **Preserve tasks across restart** and read **Statement** and **Conditions** together. The promise covers changes the service acknowledged before it stopped, on functioning local storage. If you reopen the same database, you should find the parcel in Open and the books in Completed. If you discover another book in your bag, you can reopen the original task. [Restart requirement](https://github.com/dotspec-md/dotspec/blob/main/examples/todo/specs/requirements/restart.requirement.spec.md#statement).

## Follow the requirement to its test

Open the generated requirement report. Under **Criterion**, the target is zero discrepancies across Open, Waiting, and Completed. Finding a task with the expected title is only one observation. If the service created a new task with that title and lost the old one's identity, the result would still fail. [Read the generated criterion](/examples/restart-requirement#criterion).

Under **Verification**, follow **Restart acceptance test**. The requirement's frontmatter names this function as its verification procedure. The report resolves that name to the definition. Under **Verification**, “No matching result recorded” means the report has no recorded run for that procedure. [Open the report at Verification](/examples/restart-requirement#verification).

## Run the two checks

From the root of a dotspec checkout with the alpha CLI on your path, inspect the example project.

```sh
dotspec check -C examples/todo
```

This checks the authored files, resolves the verification procedure, and checks the generated specification for drift. To observe the running app, use the checkout's pinned Go and Python tools. From the same directory with mise installed, run:

```sh
mise trust
mise install
mise exec -- python -I examples/todo/tests/acceptance.py
```

The everyday errand case compares both tasks after restart and reopens the books. A second case records **Book sink repair** in Waiting with the expected reply **Visit time from Lee**. It kills the service, starts a new process on the same disposable database, and compares the identities and titles in all three views. It also checks the expected replies and dates for both waiting entries. On success it prints `Task forms and persistence across process restart passed.` [Acceptance procedure](https://github.com/dotspec-md/dotspec/blob/main/examples/todo/tests/acceptance.py).

That run exercises a process stop after acknowledgement. A power loss or a stop during an unacknowledged write would need its own conditions and evidence. To try the books and parcel through the browser, follow the [To-do app walkthrough](https://github.com/dotspec-md/dotspec/blob/main/examples/todo/README.md#run-the-app).
