Check specifications and reference documents in a project subtree

```sh
dotspec check [<path>] [flags]
```

Check authored specifications and the reference documents they cite, using the same discovery rules as list. With no `<path>`, check covers the enclosing project; a directory narrows it to that subtree, and a specification file checks that file and the context it requests. A whole-project check in a project declared with dotspec.yaml also checks that the generated specification is current, unless build.enabled is false. With --all, check covers every project discovered in the workspace separately and exits with the highest project exit code.

A passing check means no checked file has an error finding under dotspec's automated authoring rules. Exits 1 when error findings are reported.

Learn more: dotspec docs docs/reference/inspection.md#check-specifications

```sh
dotspec check
dotspec check internal --json
```

| Flag | Default | Description |
| --- | --- | --- |
| `--all` | `false` | check every discovered project separately |
| `-h, --help` | `false` | help for check |
| `--json` | `false` | emit the result as JSON |


## Check an edited project

From the project root, check after editing the system scope. The previously built report still contains the earlier wording.

```sh
dotspec check
```

```text nocopy
specification/booking-desk.system.spec-report.md
  error [spec.content] Booking desk
  missing, altered, or out-of-order authored content: "The desk takes reservations for one hotel."

specification/booking-desk.system.spec-report.md
  error [spec.content] Booking desk
  source content missing or altered in section "scope"

specification/booking-desk.system.spec-report.md
  error [spec.stale]
  generated page is stale; run dotspec build in this project
```

## Use the result in CI

Run this as the final command in a shell step. Redirection saves the report and preserves the process exit status.

```sh
dotspec check --json > check-report.json
```

Exit 0 means the check completed successfully and may include advice. Exit 1 means specification findings prevented success. Exit 2 covers invalid invocations, missing input, discovery, file access, or output failures. Reports go to stdout, including incomplete scans. Invocation and output errors go to stderr. Inspect the scan status before relying on a partial report. A passing check assesses the authored files and report. Exercise the application separately to verify its behavior. [Inspection contract](https://github.com/dotspec-md/dotspec/blob/main/docs/reference/inspection.md) · [Restart example](/examples/restart).

Read the scope and findings guide offline with `dotspec docs docs/reference/inspection.md#check-specifications`.
